# orca-taste

## Purpose

Route frontend, landing page, portfolio, and redesign work into Taste Skill's anti-slop design workflow while ORCA keeps the delivery loop.

## When To Use

Use when the user asks for Taste Skill, design-taste-frontend, stronger anti-AI UI standards, or a frontend pass that needs product-specific layout, typography, motion, copy, and visual QA.

## Required Inputs

- Target UI, page, or redesign scope

## Optional Inputs

- Current stack
- Brand constraints
- Reference sites or screenshots
- Desired Taste Skill variant such as `design-taste-frontend`, `gpt-taste`, `redesign-existing-projects`, `minimalist-ui`, or `industrial-brutalist-ui`

## Workflow

1. Confirm the work is user-facing frontend or marketing UI.
2. Open `integrations/taste-skill.md`.
3. Pick the narrowest Taste Skill variant for the brief.
4. Keep ORCA responsible for issue context, spec, plan, implementation, QA, and receipt.
5. Require real browser or screenshot review before calling the design pass done.
6. Credit Taste Skill as upstream guidance, not native ORCA design language.

## Outputs And Artifacts

- Taste Skill routing choice
- Updated ORCA spec, plan, QA checklist, or review notes when the design pass changes delivery scope

## Related Commands And Skills

- Commands: `orca-design`, `orca-impeccable`, `orca-web-qa`, `orca-review`
- Skills: `orca-taste`, `orca-design`, `orca-attribution`
